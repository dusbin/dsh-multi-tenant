| # | 决策点 | 结论 |

## 1. 项目概述

为 DeepSeek Harness（DSH）`web` profile 开发**多租户插件**，把 DSH 从"本地单用户开发工具"扩展为"多租户、多角色、可登录、可计量、可审计"的服务形态。

### 1.1 角色模型（D1+D4）

```
平台管理员（system）           —— 管理租户生命周期（建/停/删）、全局配置、平台审计
  └─ 每个租户内：
       租户管理员（admin）      —— 用户管理/启停/角色分配、配额设置、审计查看、用量统计（自动拥有审计权限）
       审计员（auditor）        —— 租户内只读统计 + 审计日志
       使用者（user）          —— 登录、使用会话、查看个人用量与配额
```

- 用户属于且仅属于一个租户；`role` 在租户内生效；平台管理员属于特殊平台域（不占租户配额）
- **租户间完全隔离**：会话、用户、用量、审计、配额互不可见（网关 + 服务层双重强制）

### 1.2 非目标（v1 不做）

- 进程级/OS 级隔离（DSH 模型与工具同 UID，v1 不提供；文档明示安全边界，生产强隔离走容器/独立实例）
- 多机 HA / 分布式部署 / 跨进程存储共享
- 金额计费与账单（D5）
- SAML 等小众 SSO 协议

## 2. DSH 架构事实（调研结论摘要）

> 完整证据见 `docs/research/01-web-ui-architecture.md`、`02-host-plugin-architecture.md`、`03-identity-session-metering.md`

### 2.1 插件与部署模型

- profile = 组合包（bundle）patch 层 + 用户 `cordis.patch.yml`；插件 = Cordis 4 插件（`apply(ctx, config)`/`inject`/服务注册/事件）
- 插件接入方式（本机已有先例）：patch 行指向绝对路径源码（`?v=N` 缓存破坏）、软链 profile node_modules、`dsh plugin --profile web <pnpm args>`
- 双半插件：host 半（node）+ client 半（浏览器，`window.__ModuleLoader__.load({id, factory})` lazy-CJS；React 18；CSS Modules + `--dsw-*` token）
- 前端 SPA 由 Host 注入 `__ModuleLoader__` + `__DSH_BOOT__`（仅插件图）启动；`host.describe` 走连接后 RPC；**无客户端路由、无身份概念**

### 2.2 传输与信任（关键事实）

- 浏览器 ↔ host：HTTP POST `/api`（一元 RPC）+ 下行 WS `/api/events.mux`、`/api/events.host`
- `/api` 信任栅栏（loopback + `trustedHosts`）只是**可达性策略，非认证**（README 明言"Web 载体不提供认证层"）
- `--host 0.0.0.0` 被 CLI 拒绝**仅限 flag 路径**；`webserver` schema 接受 `0.0.0.0`（patch/env 可放开绑定）
- `settings.*`/`credentials.*`/`host.*`/`agentPreset.*` 等特权方法**恒钉死 loopback**（远程用户本就不该开放，符合多租户预期）
- **认证插入点（报告 02 §9 结论）**：RPC interceptor 单座位已被 api-gateway 占用；WS upgrade 无插件钩子 → **纯插件无法在 /api 分发链内完整加认证**；可行路径：A=内嵌认证反代（官方暗示出路，零改源码）、B=组合级替换 connection 行（fork，可返回 401/302）、C=上游加钩子（中期）

### 2.3 会话与计量（现成抓手）

- `ctx.sessions.create(id, {meta})`：`SessionId` 是任意品牌字符串 → **归属用 id 前缀编码 `u-<uid>-s-<uuid>`**（`meta` 无自由扩展字段）
- 真实用量链：适配器 `usage` 分片 → 日志 `assistant/chunk {type:'usage'}`（回退 `assistant/message.usage`）→ `ctx.tokenMeter.measure()` / `tokenUsage` 投影四桶（`uncachedInput/output/cacheRead/cacheWrite`）
- 无价格字段、无按用户归集、无用户概念 → 全部自建

### 2.4 存储与 RPC

- `node:sqlite` 内置可用（零 native 依赖；参考 `dsh-session-query-sqlite`：单进程单所有者、WAL）→ **主数据自建 SQLite**
- `ctx.storage.domain` KV 领域存储无事务/索引 → 不作主数据
- 客户端不能运行时注册 Typert namespace；宿主可 `ctx.connection.rpc.handle('/mt', handler, {authority})` **自建通道**（客户端 `ctx.connection.rpc.call('/mt', ...)`）→ 管理 API 走此通道
- 动态 cordis 双半插件（vm 沙箱）**不适合**做控制台 → 用静态双半包

## 3. 总体架构

```
 浏览器（登录页/控制台/聊天 UI）
   │  HTTPS/HTTP
   ▼
┌───────────────────────────────────────────────────────────┐
│ 认证网关（dsh-multi-tenant，DSH 进程内）                     │
│  · 独立监听面（网关端口，0.0.0.0）或置于反代之后              │
│  · 登录/会话 Cookie 校验（HttpOnly+Secure 可配）            │
│  · RBAC 端点级策略 + 会话归属校验（id 前缀强制）             │
│  · 配额同步检查（放行前）                                   │
│  · HTTP+WS 全量代理 → 127.0.0.1:<dsh端口>（信任栅栏放行）    │
└───────────────┬───────────────────────────────────────────┘
                ▼ 代理（loopback Host）
┌───────────────────────────────────────────────────────────┐
│ DSH web profile（原样运行，零改源码）                        │
│  /api 处理链（信任栅栏 → gateway → apiProxy）               │
│  WS 下行流 / ctx.sessions / tokenMeter / api-remotes       │
│  dsh-multi-tenant host 半（进程内）                         │
│   · 会话事件订阅 → 用量记账（按会话 id 前缀归属）             │
│   · 自建 /mt 通道：管理+租户 API（认证+RBAC）                │
│   · SQLite：tenants/users/quotas/usage/audit/auth_sessions │
└───────────────────────────────────────────────────────────┘
```

### 3.1 认证网关（部署形态 D3）

- **网关 = 插件内嵌的认证反向代理**（路径 A，报告 02 推荐）：DSH 原样绑定 `127.0.0.1:<port>`；插件另起 `node:http(s)` 监听面绑定 `0.0.0.0:<gatewayPort>`（配置项），做 TLS（可选，证书配置）/登录/会话/RBAC/配额后，把 HTTP 与 WS 全量代理到 loopback DSH——`isTrustedApiRequest` 接受 loopback Host，天然通过信任栅栏
- **公网形态**：反代（nginx/caddy）终结 TLS 后转发到网关端口（或网关自身 TLS）；**内网形态**：直接访问网关端口
- 本机直连 DSH 端口（`127.0.0.1:<port>`）默认保持开放（开发者模式，可配置 `requireAuthForLoopback` 关闭）；**对外唯一入口 = 网关**
- 备选（记录在案）：路径 B（组合级替换 connection 行）可作为"同端口、无额外监听面"的替代方案，v1 不采用（维护 fork 成本高）

### 3.2 登录与会话（D2）

| 方式 | 机制 | 依赖 |
|---|---|---|
| 邮箱密码 | `crypto.scrypt` 哈希（内置，零依赖）；登录失败计数 + 锁定 + 速率限制 | 内置 |
| LDAP | 目录绑定验证（`ldapts`，纯 JS）：配置服务器/端口/baseDN/用户过滤器；首次登录自动建号（可选） | `ldapts` |
| SSO/OIDC | Authorization Code + PKCE（`openid-client`）：配置 issuer/clientId/secret/回调；JWT 校验 + 用户映射 | `openid-client` |

- 登录成功 → 服务端会话（`auth_sessions` 表存 token 哈希，过期/登出/禁用即时失效）→ `HttpOnly + SameSite=Lax` Cookie（`Secure` 可配，HTTP 内网部署关闭）
- 同一账号可多端登录（会话表支持）；管理员可强制下线某用户（删除其会话）

### 3.3 会话归属与租户隔离（D1）

- 网关在 `session.create` 等建会话请求上**强制改写 SessionId 前缀**为 `u-<uid>-t-<tid>-s-<uuid>`（租户+用户编码），防止伪造他人前缀
- 网关对一切**会话作用域请求**校验 payload 中的 `sessionId` 前缀 == 当前登录用户 → 否则 403
- 进程内记账/管理侧按前缀解析归属；任何越界访问记审计（denied）

### 3.4 配额强制（D5，token 口径）

- 配额维度：`平台级 → 租户级 → 用户级`（叠加：生效限额 = min(用户, 租户, 平台)），周期 `daily/monthly/total`，硬限（超限即拒）
- **同步检查点**：网关放行前查 `quota.spent < limit`（进程内服务直查 SQLite，无 RPC 开销）
- **异步记账点**：进程内订阅 `session/event` 的 usage 分片 → 按会话前缀归属 → 累加（含失败请求的 usage 分片）；会话关闭补记会话级聚合
- 超限拒绝计入审计；管理员可临时放宽/重置周期配额

### 3.5 用量统计（D5，仅 token）

- 聚合维度：租户 / 用户 / 日期 / 模型 / 会话；指标：会话数、请求数、`uncachedInput/output/cacheRead/cacheWrite` 四桶、总 token
- 视图：租户仪表盘（管理员/审计员）、用户个人用量、会话明细
- CSV 导出（管理员/审计员）

### 3.6 审计日志

- 记录：登录/登出/登录失败、管理操作（用户 CRUD/启停/角色/配额/租户）、用量查询、越权尝试（denied）、系统事件
- 审计员与管理员可查（按租户隔离）；只追加、不可改删（DB 权限 + 应用层）
- 平台管理员可查全局审计

### 3.7 管理 API 与 UI

- **API**：自建 `/mt` 通道（`ctx.connection.rpc.handle`）：`auth/*`（me/logout/改密）、`tenant/*`（平台管理员）、`user/*`、`quota/*`、`usage/*`、`audit/*`（各含 RBAC）
- **UI（client 半）**：
  - 登录门禁：`shell.overlay` 全屏登录层（读 auth 状态；登录后整页刷新重建连接）——UX 层；安全真值在网关
  - 管理控制台：`settings.section` 多页签（用户管理/配额/用量/审计/租户管理），入口 `sidebar.footer.action`
  - 首启引导：`settings.onboarding`（bootstrap 平台管理员向导）
  - 个人中心：`settings.section`（个人用量/配额/改密）
  - i18n `ctx.locale`（zh/en）；`--dsw-*` token 主题

## 4. 数据模型（SQLite，`node:sqlite`）

```
tenants        id, name, status(active|disabled), config(json), created_at
users          id, tenant_id→tenants(平台管理员为 NULL/特殊域), username,
               email, password_hash, ldap_dn, oidc_sub,
               status(active|disabled|locked), role(admin|auditor|user),
               created_at, last_login_at, last_login_ip
quotas         id, scope(platform|tenant|user), target_id, token_limit,
               period(daily|monthly|total), created_at, updated_at
quota_usage    scope, target_id, period, period_start, spent_tokens,  -- 周期累计
               updated_at        （PK: scope+target_id+period+period_start）
usage_records  id, ts, tenant_id, user_id, session_id, model, provider,
               input_tokens, output_tokens, cache_read_tokens,
               cache_write_tokens, request_count
session_meta   session_id, tenant_id, user_id, title, created_at, ended_at,
               message_count, token_total
auth_sessions  id, user_id, token_hash, created_at, expires_at, ip, user_agent
audit_logs     id, ts, actor_user_id, tenant_id, action, target_type,
               target_id, detail(json), result(success|denied), ip
login_attempts user_id/ip, ts, success, method   -- 防爆破
```

- 迁移：`PRAGMA user_version` 版本化；单进程单所有者；目录 0700/0600
- 会话归属：SessionId 前缀 `u-<uid>-t-<tid>-s-<uuid>` 为权威来源，`session_meta` 表为查询加速

## 8. 风险与边界（明示）

1. **逻辑隔离的边界**：DSH 模型与工具同 UID、同进程；v1 隔离覆盖 会话/权限/配额/数据/审计 的逻辑层与网关强制。**进程级/OS 级强隔离不提供**（生产强隔离建议：每租户独立容器/独立 DSH_HOME/独立 OS 用户）
2. **特权方法 loopback 钉扎**：`settings.*`/`credentials.*`/`host.*` 对远程用户恒 403——远程用户看不到模型选择/设置等（DSH 原有限制），v1 接受并在文档明示；需开放时走 fork connection 路径
3. **网关信封改写**：会话归属前缀强制依赖对 session 域 RPC 信封的理解（有界端点集合，版本升级需跟进）；兜底：服务层前缀校验（双保险）
4. **网关代理开销**：HTTP/WS 全量代理增加一跳（进程内回环，开销可忽略）；WS 背压/SSE 流式需正确实现
5. **node:sqlite 单进程单所有者**：勿多进程共享；DSH 重启后会话恢复需重新登记 `session_meta`（从持久会话文件前缀重建）
6. **LDAP/OIDC 库**：`ldapts`/`openid-client` 为纯 JS，经 profile pnpm 安装；企业目录兼容性需实测
7. **DSH 版本演进**：0.1.1-rc.2 的 patch/slot/通道 API 可能变化（调研均已标注版本）
