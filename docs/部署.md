# 部署指南

dsh-multi-tenant 的两种受支持部署形态（方案 D3：两者都要）。认证逻辑完全一致，
差异只在"谁监听对外端口"。

## 形态 A：内网/局域网直连（最简单）

DSH 本体保持 loopback 绑定（`127.0.0.1:<port>`），插件网关绑定 `0.0.0.0` 作为唯一对外入口。

```yaml
# ~/.dsh/profiles/web/cordis.patch.yml
- insert:
    - id: multi-tenant
      name: 'dsh-multi-tenant'
      config:
        gateway:
          enabled: true
          host: '0.0.0.0'     # 对局域网开放
          port: 3090
        cookie:
          secure: false       # 内网 HTTP 部署保持 false
```

- 用户访问 `http://<机器IP>:3090` → 登录页 → 会话 Cookie
- DSH 本体端口（`127.0.0.1:3080`）只在本机可访问（开发者模式，未认证）
- **生产建议**：内网也建议用防火墙/安全组只放行 3090

## 形态 B：公网/跨网访问（反代 TLS，推荐）

nginx / caddy 终结 TLS，转发到网关端口（或 DSH 端口）。Cookie 需 `secure: true`。

### nginx 示例

```nginx
server {
  listen 443 ssl;
  server_name ds.example.com;
  ssl_certificate     /etc/ssl/ds.example.com.crt;
  ssl_certificate_key /etc/ssl/ds.example.com.key;

  client_max_body_size 300m;   # 与 DSH /api 请求体上限匹配

  location / {
    proxy_pass http://127.0.0.1:3090;   # 或 DSH 端口 3080（网关会自己加登录校验）
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;   # 网关据此构造 OIDC redirect_uri
    proxy_set_header Upgrade $http_upgrade;        # WebSocket
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 3600s;                      # 长会话/SSE
  }
}
```

```yaml
# 配置示例（公网）
        cookie:
          secure: true        # HTTPS 部署必须
        auth:
          oidc:
            enabled: true
            publicBaseUrl: 'https://ds.example.com'   # OIDC redirect_uri 用
```

### caddy 示例

```
ds.example.com {
    reverse_proxy 127.0.0.1:3090
}
```

## 数据与备份

- 数据文件：`$DSH_HOME/multi-tenant/mt.db`（SQLite，WAL 模式）
- 备份：停止 DSH 后复制 `mt.db`（含 `-wal`/`-shm` 一并复制，或先 `PRAGMA wal_checkpoint`）
- 迁移：`PRAGMA user_version` 版本化，升级插件自动迁移；**升级前备份**

## 安全边界（务必阅读）

1. **逻辑隔离而非进程隔离**：DSH 模型与工具同 UID、同进程；v1 的隔离覆盖
   会话/权限/配额/数据/审计（网关 + 服务层强制）。**同 UID 下的其他进程/用户
   可读 `$DSH_HOME`**（与 DSH 自身一致）。生产强隔离需求建议：
   - 每租户独立容器/独立 `DSH_HOME`/独立 OS 用户
   - 或至少以专用 OS 用户运行 DSH（目录 0700/0600）
2. **HTTPS 必配**：公网部署必须 TLS（反代或网关证书），否则会话 Cookie 可被截获
3. **Cookie**：`HttpOnly + SameSite=Lax`（固定）；公网 `secure: true`
4. **防爆破**：每账号+每 IP 窗口内失败计数（默认 5 次/15 分钟），连续失败达阈值
   **自动锁定账号**（管理员 `user.setStatus` 解锁时清空计数）；登录失败全量审计
5. **DSH 特权方法**：`settings.*`/`credentials.*`/`host.*`/`agentPreset.*` 对远程用户
   恒 403（DSH 原有限制）——多租户部署中本就不应向远程开放
6. **网关是唯一入口**：确保 DSH 本体端口不对外暴露（防火墙/仅 loopback）

## 常见问题

| 现象 | 处理 |
|---|---|
| 登录页显示"SSO 不可用" | 检查 `auth.oidc.issuerUrl` 可达、`publicBaseUrl` 正确 |
| OIDC 回调 302 到 `/?mt_error=...` | 按错误码查：`oidc-invalid-state`（state 过期，重试）、`oidc-exchange-failed`（client_secret/redirect_uri 不匹配） |
| LDAP 登录报"目录服务不可用" | 检查 `url`/`bindDn`/`bindPassword`/网络；错误不泄漏目录细节 |
| 远程用户看不到模型选择/设置 | DSH 特权方法 loopback-only 的既有限制（见上） |

## 运维 SOP：逃生通道 / 备份 / 恢复 / 重置

维护命令入口：插件仓库内的 `node scripts/maintenance.mjs <command>`（需本机访问，与 DSH 同信任级）。
数据文件：`$DSH_HOME/multi-tenant/mt.db`（本机 `~/.dsh/multi-tenant/mt.db`，SQLite WAL）。
备份目录约定：`$DSH_HOME/multi-tenant/backups/`（含密码哈希，保持 0700/0600 权限）。

### 1. 定期备份（推荐每日/每周）

```sh
# 手动备份
mkdir -p ~/.dsh/multi-tenant/backups
node <插件目录>/scripts/maintenance.mjs export \
  --out ~/.dsh/multi-tenant/backups/mt-backup-$(date +%Y%m%d-%H%M%S).json

# 定时任务（示例：每天 02:30，写入 cron -e）
# 30 2 * * * cd <插件目录> && node scripts/maintenance.mjs export --out ~/.dsh/multi-tenant/backups/mt-backup-\$(date +\%Y\%m\%d-\%H\%M\%S).json >> /tmp/mt-backup.log 2>&1

# 保留策略：按需清理旧文件（示例：保留 14 天）
# find ~/.dsh/multi-tenant/backups -name 'mt-backup-*.json' -mtime +14 -delete
```

备份内容：tenants / users（**含密码哈希**）/ quotas / 配额累计 / 用量记录 / 会话计量 / 审计日志；
不含临时会话与防爆破计数。**备份文件即凭据**，请按密钥保管（权限、加密、异地）。

### 2. 恢复 / 迁移

```sh
# 恢复（覆盖当前数据，事务化；目标非空时必须 --replace）
node scripts/maintenance.mjs import --in <备份文件> --replace

# 迁移到新机器：新机器装好插件后先 bootstrap 或直接 import --replace
# （import 会带入原平台管理员账号与密码，可免 bootstrap）
```

### 3. 管理员逃生通道（忘记密码 / 账号被锁 / 无可用管理员）

| 场景 | 操作 |
|---|---|
| 忘记密码 | `node scripts/maintenance.mjs reset-admin-password --username <账号> --password <新密码>` |
| 账号被锁定 | `node scripts/maintenance.mjs unlock-user --username <账号>` |
| 全部管理员不可用 | `node scripts/maintenance.mjs create-system-admin --username <账号> --password <新密码>`（加 `--force` 可强制）|
| 想用 UI | 无任何可用平台管理员时，登录页会出现"管理员恢复"表单（**仅环回来源**可用：本机访问网关/DSH） |

注意：`reset-admin-password` / `unlock` 会清空该用户全部会话与失败计数，并写审计。

### 4. 重置多租户系统

```sh
node scripts/maintenance.mjs reset-system                # 全部清空（管理面+用量）
node scripts/maintenance.mjs reset-system --keep-usage   # 仅清管理面，保留用量/配额累计
# 重置后需重新 bootstrap 创建平台管理员
```

### 5. 状态查看

```sh
node scripts/maintenance.mjs status   # 租户/用户/系统管理员/配额/用量/审计计数
```

### 6. 安全注意事项

- 备份/导出含密码哈希：权限建议 `chmod 600`，避免放入公开目录/代码仓库
- 逃生通道命令会写审计（`maintenance.*`），保留追责线索
- 恢复前请先备份当前数据（`import --replace` 不可逆）
- 定期验证备份可恢复（至少一次演练 import 到临时 `--db` 再核对 status）
